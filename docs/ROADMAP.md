## 1. Что такое MVP

Игрок заходит, видит три дорожки с монстрами, жмёт «Атака», под дорожками выпадает оружие, монстры получают урон, убитые оставляют сундуки. Монстры бьют в ответ, факел (HP) гаснет, экран темнеет. Этажи идут вниз, каждый N-й — босс. Факел погас → забег окончен, лут остаётся, плюс финальный сундук по глубине и осколки. Между забегами оружие покупается навсегда, сливается 2→1 и улучшается. Прогресс сохраняется, есть лидерборд по глубине и режим «Ярость».

**MVP готов, когда:**
1. Забег проходится от 1-го этажа до гибели без ошибок в консоли на ПК и телефоне (подтверждает владелец, не Claude).
2. Вся случайность и награды считаются на сервере, клиент только показывает.
3. Данные переживают выход/вход и перезапуск сервера (session lock, автосейв, BindToClose).
4. Контент: 6 монстров, 2 босса, 8 видов оружия, 1 редкий символ «Ярости».
5. Пройден чек-лист анти-гэмблинга (раздел 7) и аудит `roblox-dev:roblox-reviewer`.
6. 15 минут игры на телефоне без лагов и роста памяти.
7. 🔑 Монетизация включена и игра опубликована — **только когда владелец скажет**. MVP без них тоже считается готовым «к релизу».

**Не в MVP:** прочность оружия, перерождения, коллекция, колесо, буст друзей, ивенты, торговля, PvP.

## 2. Как устроена работа (решение по инструментам)

### Rojo: не используем (пересмотр решения v1)
В v1 я советовал Rojo. По опыту Artillery Legends меняю совет. **Утверждено владельцем 20.11 (`РЕШЕНИЯ.md`).**

Почему без Rojo:
- Rojo — это установки на ПК (Rojo, плагин, `rojo serve`, git), а установки только по слову владельца и ещё одна вещь, которая должна работать.
- Облачный тред не достаёт до `rojo serve` на ПК: цепочка «облако → git → ПК → Studio» всё равно требует владельца.
- Два источника правды: правка через Studio MCP перезаписывается Rojo, правки теряются.
- В AL 418 скриптов сделали через Studio MCP + Team Create без Rojo, и этого хватило.

Что берём вместо:
| Что | Как |
|---|---|
| Место | Одно облачное место с **Team Create** (сохраняет само каждые ~4 мин). |
| Код в Studio | Claude пишет скрипты через **Studio MCP** (уровень разрешений **Balanced**, не Full). |
| Код вне Roblox | Репозиторий `torchbound` на GitHub (приватный). **Ежедневный бэкап** всех скриптов из Studio в git. |
| Чистая логика и баланс | Модули без Roblox API (ролл, урон, награды, слияние) Claude пишет и проверяет **в облаке** (Luau + тесты + симуляция 1000 забегов), даже когда ПК выключен. Потом переносит в Studio через MCP. |
| Источник правды | **Studio** для всего, что в игре. git — копия и место для тестов логики. Перед переносом логики в Studio Claude сверяет, что в Studio не меняли файл руками. |

### Структура скриптов в Studio (и в бэкапе)
```
ServerScriptService/Server/     -- RunService, DataService, CombatService, LootService, ShopService
StarterPlayerScripts/Client/    -- UI-контроллеры, анимации, звук
ReplicatedStorage/Shared/
  Config/   -- Monsters, Weapons, Floors, Loot, Rage, Products (вся цифра баланса)
  Logic/    -- чистые функции: Roll, Damage, Merge, Rewards (тестируются в облаке)
  Types, Remotes
ServerStorage/Backups/          -- Torchbound_<что>_Backup_<дата>
```
Все модули `--!strict`. Тестовое помечается атрибутом `TBTest` и суффиксом «(ТЕСТ)», чтобы перед релизом убрать одним скриптом.

### Правила Studio (из опыта AL)
- Перед правкой проверить, что открыто облачное место: `game.PlaceId ~= 0`.
- Одно окно Studio. Не запускать Studio вторым экземпляром.
- Play владельца не трогать: правки только при остановленной игре.
- Перед правкой — бэкап в `ServerStorage/Backups`.
- Ctrl+S у владельца не просить чаще раза в час. Сон ПК рвёт связь.
- В Studio по умолчанию нет DataStore: сохранения проверяем либо с включённым «Enable Studio Access to API Services» (🔑 настройка владельца), либо в закрытом тесте.
- Ресурс «ПК/Studio» держит один тред: замок в `_queue/studio.md` («ЗАНЯЛ время/кто» → работа → «СВОБОДНО»).

## 3. Главный принцип плана: вертикальный срез первым

В AL 4 дня контента не доехали до игры. Поэтому здесь **сначала одна дорожка, один монстр, одно оружие целиком до телефона владельца**, и только потом партия. Каждый новый способ (анимация, эффект, стиль арта) — сначала на одном объекте, показать владельцу, потом на всю категорию.

**Ежедневный smoke-тест (с разрешения владельца, ≤ 20 мин):** зайти → начать забег → убить монстра → открыть сундук → умереть → увидеть итоги → (с д3) купить оружие → выйти/зайти, прогресс на месте. Маршрут лежит в `05_тесты/SMOKE.md`, результат строкой в `ПРОВЕРКИ_ВЛАДЕЛЬЦУ.md`.

## 6. Риски
- **Studio MCP недоступен из тредов проекта.** Запасной путь: Claude собирает `.rbxm`, владелец перетаскивает в Studio. Проверяем в 0.2.
- **ПК выключен ночью.** Ночью только работа «на бумаге»: логика и тесты в облаке, баланс, тексты.
- **Арт не успевает.** Всё на заглушках, замена ID в одном конфиге.
- **Модерация Roblox (гэмблинг).** Чек-лист ниже, платные случайные награды только с шансами.
- **Слишком много тредов.** Не больше 2–3 одновременно.

## 7. Чек-лист анти-гэмблинга
- [ ] Нет ставок: вход в забег бесплатный или за энергию, не за Robux напрямую.
- [ ] Любой забег даёт гарантированный минимум.
- [ ] Для платных случайных наград показаны шансы.
- [ ] В текстах нет «ставка», «казино», «джекпот», «слот», «бет».
- [ ] Арт, название и звуки не копируют Kill Em All / Nolimit City.
- [ ] Вся случайность и выдача наград на сервере.
